# 双端 UI 与交互约定

更新：2026-09-10。**这是统一目标及当前差异说明，不代表两端均已落实。**

## 视觉基础

| 项目 | 约定 |
|---|---|
| 基础配色 | 炭黑 `#101113`、暖金 `#E3CAA1`；正文高对比，次要文字弱化 |
| 主次操作 | AI 调色为金色主操作；保存副本为清晰可辨的次操作 |
| 照片 | 编辑页优先展示，保持比例；比较图的分界必须对应同一图像坐标 |
| 页面层级 | 换图入口紧凑；样片、摄影来源、参数详情不抢占编辑首屏 |
| 触控及辅助功能 | iOS 关键操作至少 44pt、Android 至少 48dp 为项目设计目标；支持状态读出和大字体滚动 |
| 布局原则 | 以平台原生单位实现，不追求两端像素完全相同 |

当前 Android 主主题定义在 `ui/theme/Theme.kt`，iOS 色彩编辑器定义在 `ColorEditorView.swift`。没有跨平台共享 token 包，部分相机旧控件仍使用白、蓝、黄，应逐项核对后统一。

## 状态与行为

- 读取、AI 分析、渲染和导出是不同阶段，状态文案应反映实际阶段。
- 忙碌时同时提供说明及适用的取消入口，不能只有灰色按钮。
- 渲染完成与 AI 返回成功分开；参数变动后，旧预览不可作为新配方导出。
- 失败保留最近有效结果，重试不隐式重复付费请求。
- 保存称“保存副本”，用户仍需到系统相册核对；不要暗示覆盖原片。
- 小数显示不得把细微非零调整误导为“没有效果”；UI 单位必须说明。

## 真人检查清单

两端统一为“拍摄检查清单”，分组“拍摄前 / 取景拍摄 / 拍摄后”。状态固定为“待检查 / 已确认 / 有问题 / 不适用”。问题项不得计入已确认；状态不能只靠颜色表达。重置要求确认，导出由使用者主动触发。允许 SwiftUI Menu 与 Compose DropdownMenu 使用各自原生外观。

## 当前尚未统一

1. Android `aaedda6` 已实现照片优先布局、独立样片入口、折叠参数、底部阶段状态和大字体纵向操作按钮；已编译，尚待两端截图与真人对照。
2. Android RGB 已与 iOS 一样显示四位小数通道偏移（±0.0800）；仅总效果强度显示百分数。基础参数滑杆范围尚需逐项核对。
3. iOS Key 生命周期为编辑器，Android 为进程。
4. Android 初始显示原图，离线建议改为主动选择；增加实际预览像素差异统计。拍照结果与保存的页面顺序仍不同，原生控件外观也并非逐像素相同。
5. Android 当前 Activity 锁定竖屏，横屏不是已支持的统一能力。

每次修改附小屏、默认字体、最大辅助字体及忙碌/失败状态证据。当前覆盖和待办以 [KNOWN_ISSUES.md](../testing/KNOWN_ISSUES.md) 与 [验收表](../testing/CROSS_PLATFORM_ACCEPTANCE.md) 为准。
