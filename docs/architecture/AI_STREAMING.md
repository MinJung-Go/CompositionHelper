# AI 调色流式预览计划与实现

## 目标及实施顺序

1. 双端改用 Gemini `streamGenerateContent?alt=sse`，保持一次请求，不自动重试或增加付费调用。
2. SSE 事件完整后拼接非 thought 文本；仅对闭合的顶层参数组生成临时方案。
3. 临时预览最长边 640 像素，最多每 500ms 启动一次；完整方案成功渲染后才提交正式配方、撤销历史及最近 AI 方案。
4. 增加协议、失败恢复及禁止临时保存测试；构建两端并记录待验收项。

## 用户行为

- 点击 AI 调色后保留原来的正式结果，显示“正在发送照片并等待首个结果”。
- 基础参数完整且校验通过后展示临时照片，标注“临时预览 · AI 仍在完善调色”。
- 后续完整参数组逐步更新；未完成的数字、字符串、数组不补齐、不渲染。
- 临时阶段禁止保存和手动修改。取消或失败撤回临时图，保留请求前的配方和历史。
- 必须收到 STOP、验证完整 JSON，并成功生成正常分辨率预览，才允许保存副本。
- 模型未按建议顺序输出或一次返回全部内容时，可能没有中间预览；不伪造进度百分数。

## 实现边界

- Android：`ColorStreamDecoder.kt`、`GeminiColorClient.kt`、`ColorEditorScreen.kt`。OkHttp 回调消费 SSE，合并待处理的中间结果，取消时关闭请求。
- iOS：`ColorPlan.swift` 中纯逻辑解码器、`ColorPhotoService.swift`、`ColorEditorModel.swift`。URLSession 按字节组行，正确保留 SSE 空行；代次标识和取消检查隔离旧请求。
- 完整响应上限 256KB，方案上限 64KB；忽略 thought 内容，不显示内部推理或原始 JSON 到阶段状态。
- 流式不降低原尺寸导出质量，不把临时 640 像素图用于保存。
- 模型参数组顺序由提示词建议，未增加强制 JSON Schema，因此不能保证首个效果出现时间。

## 耗时与隐私

“调整详情”记录从本次请求流程开始至首次有效参数、首次临时预览、完整响应处理结束的秒数，以及最终渲染秒数。完整响应耗时包含本地消费和临时预览开销；不是纯服务器耗时。暂未独立测量上传阶段。没有新增遥测上传，不记录密钥、照片或模型原始响应到日志。

## 验证计划

- 纯协议：任意字符分块、中文与转义、未完成数字/数组、SSE 注释与多行、thought、usage、缺失 STOP、MAX_TOKENS、被拦截、截断、过大响应、后续越界参数。
- Android 设备用例：临时预览期间保存禁用；取消保留原图；失败恢复原有 AI 配方。设备用例编译不代表执行通过。
- 真人验收：两端分别测试正常流式、慢网络、中途断网、取消后重试、退出编辑器、换照片、后台恢复与相册副本。至少记录 3 次首预览/总耗时，且使用同一模型、照片与网络比较。
- 没有真实 Gemini 请求的实测速率证据前，不承诺缩短秒数或倍率。

参考：[Gemini 流式接口](https://ai.google.dev/api/generate-content)、[结构化输出](https://ai.google.dev/gemini-api/docs/structured-output)。

## GLM 扩展（2026-09-11）

双端新增智谱 `glm-5.3-flash`，复用配方校验、临时预览及提交/撤销逻辑。GLM 使用 Chat Completions SSE，保持 `thinking.type=enabled` 和 `reasoning_effort=max`；仅正式 content 更新预览。详见 [协议与测试说明](../guides/GLM_TESTING.md)。原 Gemini 256 KB 响应限制保持，GLM 允许 2 MB 以容纳思考事件，两端配方均限制 64 KB。
