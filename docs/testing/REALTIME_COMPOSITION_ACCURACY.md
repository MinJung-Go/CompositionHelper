## 本轮目标

根据[实拍验证报告](REALTIME_COMPOSITION_VALIDATION.md)，改善主对角线漏检、人像构图定位和多人主体跳变。验收分别统计单帧候选、稳定后的提示、原生检测与实际设备表现。

## 实现

- 对角线仍使用 Android OpenCV LSD、iOS Vision 轮廓。把短缺口两侧的共线线段合并，检查真实覆盖、方向、是否贯穿画面中部及双侧同向亮度差。拒绝只有半边的透视汇聚线、缺乏亮度边界的细线及多组近似平行长边。每帧最多评估 24 条种子线段。M-LSD 保留在离线对照中。
- Android 使用随包分发的 ML Kit 人脸检测，iOS 使用系统 Vision 人脸关键点。优先采用双眼都落在可见画幅内、间距和姿态合理的人脸。合影按相邻帧的脸框重叠和锚点距离关联，连续失配才重新选人。没有可信双眼时用原平台的通用主体检测。可靠的人像位置与其他构图证据走原来的推荐评分。
- 两端沿用 200 ms 采样间隔和两帧推荐稳定逻辑。相机退出、重绑及画幅变更按原有生命周期重置识别状态。Android 新增随包人脸库，需检查最终 APK 的 16 KiB 对齐与运行。

## Android 实拍回归

在 Windows 以和基线相同的中心正方形与 5 Hz 时间采样运行 OpenCV 4.12 LSD，再把候选和灰度送入功能提交 `57033f6` 的 Kotlin 证据评分与稳定逻辑。桌面回放未运行 ML Kit 主体竞争。使用的是设计阶段已知的 15 段录像，不能从这批素材外推泛化准确率。

| 检查 | 基线 LSD | 适配后 LSD |
| --- | ---: | ---: |
| 主对角线单帧检出 / 60 | 0 | 20 |
| 主对角线稳定提示 / 60 | 0 | 17 |
| 有稳定提示的正例 / 3 段 | 0 | 1 |
| 负例稳定误提示 / 200 | 0 | 0 |
| 旧合成正例单帧检出 / 36 | 30 | 28 |
| 旧合成负例单帧误判 / 36 | 12 | 2 |

跨线桥有 15 帧候选和 17 个稳定提示采样点。工业铁路 5 帧分散命中，未连续稳定。城市车道仍漏检。旧合成集的两个误判来自斜率 0.47 和 0.55 的离轴样本，保留旧标签计为误判。旋转楼体边界样本稳定提示从 2 增到 9 个采样点，仍需和真正的主导结构区分。桌面几何及亮度评分 P95 约 0.29 ms，含候选拼接和筛选，录像解码、线段提取、原生人脸检测和相机渲染另计。

Android 本地 Java 17、Kotlin/JVM 和 JUnit 运行规则及画幅检查，11 项通过。逐帧结果和重跑入口在本机 `artifacts/realtime-composition-adaptation-2026-11-08/android-replay.zip`。
