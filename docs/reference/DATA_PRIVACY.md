# 数据处理与隐私说明

更新：2026-09-11。描述当前代码的数据行为，供使用者与开发者核对；不代表第三方服务的数据政策，也不是已经完成商店审核的声明。

## 数据去向

| 数据 | 处理与保存 | 何时离开应用 |
|---|---|---|
| 相机帧、构图检测 | AVFoundation/Vision 或 CameraX/ML Kit 端侧处理；当前构图代码不上传这些帧至 Gemini | 无项目实现的云端构图上传 |
| 导入照片 | 使用所选 URI 或 Data 读取、纠正方向并生成预览；原图不作为 AI 请求直接发送 | 仅使用者点击 AI 时发送重新编码的 JPEG 缩略图及提示词，不附原片 EXIF |
| 调色配方 | 用于本机预览、撤销与副本导出；无项目云同步 | 无自动上传配方到自建服务 |
| API Key | Android：进程级会话内存；iOS：编辑器实例内存。可主动清除 | 发给所选 Gemini 或智谱 GLM 固定 HTTPS 接口的请求头；不写入 URL、项目或安装包 |
| 清单结果、备注 | Android SharedPreferences；iOS UserDefaults / AppStorage；本机保存 | 仅选择“导出检查记录”后通过系统分享操作交给所选接收方 |
| 保存的照片副本 | 系统相册/MediaStore；JPEG 有损编码，保留原片 | 系统相册自身的同步行为由用户系统设置决定 |

不能从“未发送原片 EXIF”推断照片内容不含个人信息：缩略图仍可能包含人脸、文字或位置线索。所选服务商的账号、配额及数据处理以所使用的服务设置为准；应用不实现自己的账号、配额或后端代理。

## 清单持久化与删除

状态键为 `shooting.checklist.v1`，备注键为 `shooting.checklist.notes.v1`。不存在清单账号同步。确认“开始新一轮检查”会清除这两个记录，不删除照片；取消重置不改变记录。分享出的文本副本由接收应用管理，重置不会撤回这些副本。

Android 当前备份 XML 只包含应用文件目录 `shared/`，不包含清单 SharedPreferences，因此不能承诺清单随应用备份迁移。iOS 清单使用标准 UserDefaults，未实现专门的备份排除逻辑；系统备份/恢复可能保留它，不能把“无云同步功能”表述为“绝不进入系统备份”。卸载、清除数据或恢复操作可能丢失或恢复记录，重要记录先导出。

## 凭据与网络

两端直接连接所选 Gemini 或智谱 GLM，禁用重定向并限制响应大小。真人清单和手动调色不要求 AI Key。不要把共享 Key 写入源码或构建配置；当前设计要求使用者自行配置。

iloader 的 Apple 账号验证属于外部安装工具，与 CompositionHelper 的 AI Key 是两套不同流程；本应用没有 Apple 账号输入或登录模块。

## 权限与验收

相机权限用于取景和拍照，照片选择及保存使用各自平台的系统流程。Android 仍保留部分旧相册权限入口，待按系统选图方案进一步梳理；API 24–28 保存权限需实际设备验证。拒绝、撤回、重新允许权限后的行为见 [验收用例](../testing/CROSS_PLATFORM_ACCEPTANCE.md)。

后续引入遥测、后端、同步或新的 SDK 时，先更新本表和实际权限/备份配置，再发布；不要沿用这份说明来覆盖尚未检查的新数据流。

GLM 使用 `open.bigmodel.cn` 通用 API，默认 GLM-5.3-Flash，保持深度思考；思考内容只在网络事件解析期间短暂存在，不显示、不持久化、不参与调色。详见 [GLM 测试指南](../guides/GLM_TESTING.md)。
