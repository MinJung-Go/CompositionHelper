## 已实现

照片 URI → 正确方向的 sRGB 缩略图 → 用户点击 AI 调色 → Gemini 返回 JSON → 参数校验 → 本地渲染 → 左右对比、强度与手动调整 → 原尺寸 JPEG 副本。

- 默认左右对比，左原图、右调色后；可单独查看。
- Gemini 看实际照片制定方案，不依赖固定场景预设；不使用 SAM 或生成式重绘。
- 处理顺序与两张效果样片实验一致：基础七参数 → RGB 九点曲线 → 羽化 HSL 色域 → 按亮度加权的 RGB 色彩平衡 → RGB 校色 → 最终强度混合。
- HSL 对低饱和中性色作平滑保护，对重叠色域归一化；色域横跨色相零点时仍平滑。
- 同一份不可变方案同时用于预览和导出；强度 0、重置均为像素恒等变换（JPEG 保存仍有有损压缩）。
- AI 请求可取消，有连接、读取和总超时；无自动重试，避免意外重复调用。失败不覆盖当前编辑。
- 支持最近 20 次操作撤销、恢复最后的 AI 方案、离线基础调整；拖动滑块整体记为一次撤销操作。当前方案、强度、最后 AI 方案支持状态恢复，撤销历史仅在当前页面实例保留。
- 只在当前预览与参数对应时允许导出，快速拖动会取消过期渲染；导出锁定方案并逐行检查取消，未完成的相册项目会清理。

## 设置与数据

右上角 AI 设置：API Key 与模型名称。默认沿用这次样片测试使用的 `gemini-3.5-flash`；账号不能访问时可以修改为支持看图与 JSON 的 Gemini 模型。模型可用性与账号相关。

API Key 仅存进程内存，不写入项目、APK、磁盘、状态 Bundle 或日志。应用进程退出后重新填写，可主动清除。上传的是 JPEG 缩略图，不附带原片 EXIF；只有用户点击 AI 调色才会上传。网络固定使用 Google HTTPS 域名，禁止重定向，不将密钥放在 URL 中。

当前为用户配置自己的 Key 的试用版。如果要发布供多人共用额度的正式产品，应另设后端代理、登录与配额，不能将共享密钥打包到 APK。

模型返回不完整、被拦截、缺少基础参数、非数值或越界参数、非单调曲线、重复/未知 HSL 色域时，整个方案会被拒绝，当前图像保留。错误提示不展示模型原始响应或请求头。

## 边界

按色域与亮度调整不等于精确对象选择，天空、水面或衣服的相近颜色可能一起变化。JPEG 中已丢失的高光细节无法恢复。大图原尺寸导出使用 CPU 并占用原图与结果图内存，内存不足会提示，不降低输出尺寸。API 24–25 的色彩管理及不同厂商设备仍需真机验收。

接口依据：[Gemini generateContent](https://ai.google.dev/api/generate-content)、[图片理解](https://ai.google.dev/gemini-api/docs/image-understanding)。

## RGB 与互补色校正

入口：色彩工作室 → 手动精调 → RGB 校色。可选整体、阴影、中间调、高光，分别调整红—青、绿—品红、蓝—黄。正值向原色方向，负值向互补方向；面板数字为 sRGB 通道偏移的百分数（±8 对应 ±0.08）。

两种模式不等价：`direct` 直接增减对应原色，`complement` 反向增减另外两个通道。以补红为例，前者加 R，后者减 G、B，亮度和饱和度可能有不同变化。一次只选择一种模式，该模式用于本组全部明暗分区。

AI JSON 新增可选 `rgb_correction`，包含 `mode` 和 `global/shadows/midtones/highlights` 四组 `[r,g,b]`，各值限制在 [-0.08,0.08]。缺失字段默认零，旧方案保持原效果。算法在旧色彩平衡输出截断后、总强度混合之前执行；在此时的 sRGB 亮度 y 上固定计算阴影、中间调、高光权重 `(1-y)^2, 2y(1-y), y^2`，权重和为 1，再叠加整体偏移。互补模式将轴值变换为 `[-g-b,-r-b,-r-g]` 后应用，最后截断。

预览、导出、撤销、重置、恢复 AI 方案及状态恢复共用完整方案。AI 提示词要求从可能的中性物体和现场光照判断偏色，不按颜色数量或直方图总量拉平 RGB，避免与白平衡重复校正。此功能属于通道偏移校正，不是 Adobe 三原色校准或独立 RGB 曲线。

新增 8 项 JVM 回归覆盖两种模式的亮度差异、三轴正负方向、明暗权重、强度与 alpha、极端值截断、保存及模型响应往返、旧方案兼容、非法参数拒绝。设备交互和真实模型新参数输出仍需设备验收；本次没有消耗 API 额度。
